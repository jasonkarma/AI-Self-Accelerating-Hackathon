# Implementation decisions

1. SPEC v1.2 wins over v1.1: model features are exactly 299-dimensional; six risk components remain separate.
2. `tau_dev = 1 - tau_risk`; qualification is `y_dev >= tau_dev`, equivalent to `Risk <= tau_risk`.
3. The bundled fixture is always marked synthetic. Real-data ingestion adds `source_is_real` before freezing.
4. AUBQC preserves the preregistered `1/30` scaling even though seven five-query checkpoints are reported.
5. Contract phase strings are mapped at the API boundary to the shorter labels in `api_contract.json`.
6. M5 policy mode is persisted in benchmark output and ledger metadata (`adaptive_tool` or `live_agent`).
7. A truncated-memo crash is fixed by raising the **ceiling**, not by lowering deliberation: reasoning tokens are billed against `max_tokens`, so `finish_reason="length"` on a 140-word prompt means the model never finished thinking. Affinity moved 4096 -> 8192 (the gateway was probed and accepts 16384/32768 too), and every seat now honors `<SLUG>_MAX_TOKENS` because the usable cap is a gateway property, not a model property.
8. Fallback seats inherit the primary seat's `max_tokens`/`timeout` through `AgentModel.rehomed()`; rebuilding them bare silently reset a re-homed run to the 1024 dataclass default, which is exactly the class of bug that crashed Affinity.
9. `delta_vs_wt` is `round(best_qualified_binding - reference, 3)`. The reference is the measured WT when the queried pool contains it (synthetic fixture) and otherwise the frozen q=5 **seed baseline** — the same checkpoint the matched M1–M4 curves start from. It is resolved once and memoised so a later reveal cannot move the anchor underneath the KPI. The dataset's WT *label* is never read: the official 1N8Z export contains no measured `SRWGGDGFYAMDY` row, and SPEC §2 confines `y_bind` access to `BindingOracle`. The old code only looked for a row with `candidate_id == "WT"` (absent in the real export, and never seeded by `Campaign`), so the delta stayed hardcoded at `0.0` while `best_qualified_binding` climbed.
10. Every slot is spent on a **developability-qualified** candidate (`y_dev >= tau_dev`), in the live campaign and in every benchmark method. `y_dev` is sequence-derived and free at `t=0` (SPEC §2), so gating on it leaks nothing, and an unqualified pick can never move `best_qualified_binding` or AUBQC — it is pure waste. `qualified_pool()` returns the unfiltered frame only when fewer than five qualified candidates remain, so the gate can never under-fill a batch.
11. Hypotheses are graded as a **paired H1/H0 experiment**, not against a cross-round median. Slot 4 is the H1 arm (a candidate the agents' `Δ_agent` boosts), Slot 5 is the H0 null-baseline control (the best remaining candidate on `A_base`). The null hypothesis is `Δ_agent == 0` — the candidate M3 would query next — **not** `Δ_agent <= 0`; the earlier non-positive filter made the lab boycott its own proven substitutions for 20% of every early batch, which is anti-agent sabotage, not a control. `audit_past_hypotheses` compares the two revealed bindings: control wins ⇒ `FALSIFIED`, H1 wins ⇒ `SUPPORTED`, tie ⇒ round median, then pre-query expectation. Because the comparison is inside the batch, it is causal rather than descriptive, and every completed round lands on a definitive verdict.
12. Self-correction is real, not cosmetic: a `FALSIFIED` round reports the positions it actually **tested** (`_tested_positions` — only rules whose preferred residue the Slot 4 candidate carried), and those positions are **inverted** by `adaptive_prior_score` in every subsequent round. Inverting every declared position would blacklist most of the CDR3 within a few rounds; inverting only the tested rule keeps the correction proportional to the evidence.
13. `Δ_agent` is bounded to `±0.06` and built from two terms: the council's **summed** positional priors (averaging over 13 positions diluted one confident rule to `weight/13`, which made the agents' vote invisible next to `A_base`) and an empirical-Bayes **SAR** term over surrogate **residuals** (`y_bind - mu_bind`), because the surrogate already absorbs additive multi-mutation structure — a candidate that measured high *and* was predicted high says nothing about its individual substitutions. Effects shrink by `n / (n + 3)` and cells with `n < 2` contribute zero, so cold-start singletons are damped automatically and confirmed multi-observation SAR steers later rounds. No round switch is needed.
14. Slot 3 is an **optimistic multi-beta UCB**, not raw `max sigma_joint`: it maximises `A_H1 + 0.50 · VoI · sigma_joint`, where `VoI = H · (1 - 0.65 · C)` combines the remaining post-batch horizon with empirical SAR convergence. The exploration weight falls to zero once the SAR term is corroborated (or on the final batch), so slot 3 degenerates to pure exploitation without a hand-written phase switch. Unconstrained `max sigma_joint` picked the least-informed candidate in the pool regardless of whether it could ever win, which is how unqualified candidate `CAND-286` (`y_dev=0.449`) reached Slot 1. `VoI` no longer toggles a "harvest mode": slot 5 tests the null baseline on every batch.
15. Rules 10–14 are implemented **once**: `core/baselines.run_method` delegates M5 to the same `select_five_slots` portfolio the live campaign calls, passing its own priors through a stand-in `RoundDecisionRecord`. Benchmark M5 and live M5 therefore cannot diverge, and the falsification feedback loop runs in both.
16. Decisions are persisted as `round_decision` ledger events (carrying the measured slot ids and pre-query expectations), and `Campaign._hydrate_from_ledger()` replays them plus the reveal rounds. `scripts/run_campaign.py`'s documented "continue from an existing ledger" mode therefore keeps its round counter, verdicts, KPIs and AUBQC instead of restarting at 0/0 with `delta 0.0`.
17. `M5` is **the agents on top of the unbiased surrogate**, not M4 plus the agents. `loop_prior_score` (WT anchor conservation on `W3, Y11, D12, Y13` plus the >3-aromatic penalty) stays M4's objective alone: on the real 1N8Z table M4 finishes behind plain UCB because the highest-affinity HCDR3 variants start `AR...` and carry 4–5 aromatics (`...YYFDY`), so the static textbook prior penalises exactly the good binders. Chaining `A_null = A_base + loop_prior` made M5 inherit that bias in rounds 1–3 and trail M3 at q=10/15/25. `A_null` is now `A_base` (the clean dual-surrogate UCB score, i.e. `Δ_agent = 0`) and `A_H1 = A_base + Δ_agent`. M4 keeps the fixed prior, which is what proves the point: a static expert rule fails under HCDR3 epistasis, while strictly empirical-Bayes residual SAR + council priors do not.
18. The CLI's final CAMPAIGN STATE prints a compact q=35 table containing `live M5` **and** `M5 (10-seed)`, labelled distinctly. They answer different questions — the 10-seed number is the same policy family run ten times, the live number is one council-driven campaign — so they are reported side by side and never averaged.
19. Four **self-learning benchmarks** are reported beside AUBQC, because "best single molecule found" is a weak claim about a learning loop: `normalized_aubqc` (headroom fraction between seed score 0.0 and pool ceiling 1.0), `top5_panel_aubqc` (mean of the best five qualified leads, i.e. portfolio depth, which does not punish exploration slots that surface non-binders), `spearman_rho_curves` (scoring model vs true binding over the qualified pool — the only number comparable to AbBiBench zero-shot baselines on 1N8Z: AF3 `-0.16`, ProteinMPNN `-0.17`, ESM-2 `-0.13`), and `top_decile_hit_rate` (fraction of the 30 post-seed queries landing in the pool's top decile). Undefined rank correlations are reported as `null`/`n/a`, never as `0.0`: M1 has no scoring model at all, and averaging its absence in as zero would be a claim the data does not support.
20. The benchmark's paired audit now inverts only the rules the Slot 4 candidate **actually exercised**, via the same `_tested_positions` helper the live path uses. It previously inverted the entire declared prior list, which blacklisted most of the CDR3 within three rounds and made benchmark M5 diverge from live M5 — the exact split `core/baselines.py` exists to prevent.
